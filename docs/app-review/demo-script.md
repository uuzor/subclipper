# Demo account and demo video

TikTok and Meta both ask for a recorded demonstration, and both want to be able
to exercise the product themselves. This is the shared material: the seeded
project, the review credentials, and a shot list whose every shot maps to a
permission in the application.

## The demo account

The reviewer must be able to reach the publishing feature without supplying
their own hour-long podcast. Provision a review tenant with a project already
processed to the point of having scored clips, so the first thing the reviewer
sees is a populated workbench, not an empty state.

**Credentials to include in the form** (create them fresh for the review, and
rotate them once the review closes):

| Field | Value |
| --- | --- |
| URL | `https://clipviralmoment.com` |
| Email | `appreview@clipviralmoment.com` |
| Password | *(set at filing time; not stored in this repo)* |

The account must have:

- One project already processed, with at least three scored clips and at least
  one rendered to 1080×1920 with burned captions. Use content the reviewer may
  legitimately see — a public-domain lecture, or content we own. Do not seed it
  with third-party material we do not have the rights to.
- One clip scheduled to a **private** test account on the platform under review,
  so the reviewer can see the scheduling UI without publishing anything public.

### Seeding it

The pipeline is deterministic in mock mode, so the project can be built by
generating a synthetic source and running it. Generate the sample the way
`examples/clips/README.md` does, so the demo contains no third-party footage:

```bash
# 0. A synthetic long-form source (speech over a plain background). No
#    third-party footage is used anywhere in the demo.
sudo apt-get install -y espeak-ng
espeak-ng -v en-us -s 150 -w /tmp/speech.wav \
  "The biggest mistake I made was trusting everyone. University degrees do not guarantee success."
ffmpeg -y -f lavfi -i "color=c=navy:s=1280x720:d=20" -i /tmp/speech.wav \
  -shortest -c:v libx264 -preset ultrafast -pix_fmt yuv420p -c:a aac sample-longform.mp4

# 1. Create the project and upload the sample.
curl -sS -X POST "$BASE/api/v1/projects" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Demo: review walkthrough","authorized_by":"QuickReel",
       "license_note":"Synthetic sample generated by QuickReel; used for app review"}' \
  | tee /tmp/project.json

PROJECT=$(python -c 'import json,sys;print(json.load(open("/tmp/project.json"))["id"])')

curl -sS -X POST "$BASE/api/v1/projects/$PROJECT/upload" \
  -F "file=@sample-longform.mp4;type=video/mp4"

# 2. Run the pipeline (synchronous when QUICKREEL_TASK_ALWAYS_EAGER=true).
curl -sS -X POST "$BASE/api/v1/projects/$PROJECT/process"

# 3. Render the top clip to vertical with captions.
CLIP=$(curl -sS "$BASE/api/v1/projects/$PROJECT/clips" | python -c \
  'import json,sys;print(json.load(sys.stdin)[0]["id"])')

curl -sS -X POST "$BASE/api/v1/projects/$PROJECT/render" \
  -H 'Content-Type: application/json' -d "{\"clip_ids\":[\"$CLIP\"]}"
```

For a demo that reads as a real podcast rather than a synthetic one, use a
recording QuickReel owns outright. Do not seed the review account with a
downloaded third-party podcast: the rights question is the one this product must
never invite.

## The demo video

Record at 1080p, no cuts between unrelated screens, and keep the cursor visible
so the reviewer can see that each action is a real click. Narration is optional
but a caption bar naming each step is not: reviewers watch with the sound off.

Target length: **3–4 minutes.** Both platforms cap uploads at 5 minutes for this
purpose, and a tight video that shows the whole loop is more convincing than a
long one that drifts.

### Shot list

| # | Shot | What it proves | Permission justified |
| --- | --- | --- | --- |
| 1 | Sign in to the demo account. The workbench loads with the seeded project and its scored clips. | The app is functional and the reviewer is not starting from an empty state. | — |
| 2 | Open the seeded project. Scroll the clip list: each clip shows a viral score and a time range. | The core feature (moment detection and scoring) is real. | — |
| 3 | Open one clip. Play it. Point out the 9:16 framing and the burned captions. | The rendered output is a real vertical video, not a placeholder. | — |
| 4 | Go to **Accounts**. Show the platform cards and the **Connect** button. | This is where consent is requested. | all scopes |
| 5 | Click **Connect** on TikTok. The platform's own consent screen appears, listing the requested scopes. Approve it. | Consent is the platform's screen, not ours; the user sees exactly what is granted. | `user.info.basic`, `video.publish` |
| 6 | Back in **Accounts**, the connected account now shows the account name and a connected state. | `user.info.basic` is used for a real, visible purpose. | `user.info.basic` |
| 7 | On the clip, open **Schedule**. Pick the connected account, choose a time a few minutes out, and confirm. | The user takes an explicit action; nothing posts on its own. | `video.publish` |
| 8 | The scheduled post appears in the post list with a **scheduled** status. | The action is recorded and reversible. | — |
| 9 | Wait for the scheduled time (or use the publish-now path in the demo account). The post publishes. Show the post on the platform's own app, in the private test account. | The publish actually works end to end. | `video.publish` |
| 10 | Back in **Accounts**, disconnect the account. The connection disappears. | Access is revocable and revocation takes effect. | — |

### What the narration should say at shot 5

The single sentence reviewers listen for:

> "QuickReel asks for permission to publish videos to your account and to read
> the account's basic name so the app can label the connection. It cannot read
> your messages or followers, and it never posts without you scheduling a clip."

## Notes on what not to show

- Do not show a clip rendered from third-party content in the demo. Even in a
  private review account, a reviewer who recognises copyrighted footage will
  question the rights position, which is the one question this product must
  never invite.
- Do not narrate a feature that is not built. The performance loop is live and
  reads engagement counters for posts this app published; it does not read
  audience insights, and the scoring weights are not yet recalibrated from the
  data, so do not present the learning side as active.
